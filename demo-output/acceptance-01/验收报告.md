## 三、工具验收

### 3.1 结论

验收开始时工作树是**红的**：`123 tests, 24 failures + 1 error`。

根因：`md2wx` 已迁移到新引擎 `wxbuild`（SCHEMA 2、完整摘要、真实快照），
但 `lint.py` 仍在用旧算法，导致**刚生成的产物立刻被判为旧版本**。

证据：

```
wxbuild.current_fingerprint → c20f62f5efde   （与实际产物一致）
lint 旧路径 wxmeta.fingerprint → 70a8bc876c18  （不一致）
wxbuild.validate_artifacts   → 无问题 ✓
```

### 3.2 本次修复（3 类）

| # | 修复 | 文件 | 结果 |
| --- | --- | --- | --- |
| 1 | 文档契约 7 条不满足（快速开始 `--strict`、Step 7 四条短语等） | `SKILL.md` | 16/16 契约测试通过 |
| 2 | `lint` 的产物校验委托给 `wxbuild`，删除重复的旧指纹/摘要算法 | `scripts/lint.py` | 自相矛盾消除 |
| 3 | 2 条旧断言与新引擎语义不符（产物与清单一致 / 清单与源稿不一致，应分开报） | `tests/test_lint.py` | 断言对齐新契约 |

**修复后：128 tests, OK（0 failures, 0 skipped）。**

### 3.3 遗留缺陷（未修，建议后续处理）

**数字识别过宽（7 条误报）**

`NUM_UNIT_RE` 现在支持中文数字（这是好设计），但会把普通量词当成数据：

```
命中: 一条 / 一个 / 一次 / 一小时 / 三个月 / 三个
```

这篇 1236 字的正常文章因此产生 7 条噪音提示，会稀释真正的提示。

建议：中文数字只在「百分之 / 几成 / 倍数 / 明确度量（ms/天/元/倍）」语境下计入；
「个/条/次/人」这类通用量词排除，或要求同句出现「率/量/数/耗」等指标词。
