# 文章转视频 skill 第一版设计

## 已确认目标

输入文章，交付 2–3 分钟中文知识型 MP4，9:16、1080×1920、30 fps，画面以动态图文为主。在线预设音色配音，本地可编程渲染。用户于 2026-11-12 要求先实现第一版、后续逐步调整，因此不再等待逐项设计确认。此次不提交或推送 git，不调用付费配音、不外发实际文章。

## 范围与边界

- 独立目录 `skills/article-video/`，不改变 `skills/wechat-mp/` 的脚本接口。
- Markdown/纯文本/粘贴正文先落地为本地文件，再摄入为带段落编号、SHA-256 的 `source.json`。网页正文由执行 Agent 使用已授权的获取工具提取，抓取不完整即停止；首版不提供任意 URL 抓取器。
- Agent 负责理解文章、改写旁白和分镜，脚本不宣称自动理解自然语言。保留事实、引用和主旨，记录删减；数字及结论需对应原文段落，来源对应不等于独立事实核实。
- 默认生成 8–14 个场景。五种版式：hook、points、steps、compare、summary。每句字幕独立合成一段音频，以实际音频长度安排字幕，不伪造逐字时间戳。
- 在线适配器采用 Azure Speech REST，默认 `zh-CN-XiaoxiaoNeural`，地区通过环境变量提供；首版只支持公共 Azure 区域端点。密钥只读环境变量，不写入产物或日志。REST 请求不自动重试，避免重复计费；错误显式失败，不静默改用其他服务。
- 提供显式 `demo-local` 模式，用 macOS `say` 生成自有示例文章的测试音频，仅验收本地流水线，不称为在线音色成片。正常任务不能偷偷降级到此模式。
- 不包括 AI 视频镜头、声音克隆、音乐检索、自动发布、剪辑软件工程或横屏适配。

## 文件契约

`source.json`：`version:1`、`sha256`（原始源文件字节）、`text`、`paragraphs:[{id,text}]`。

`plan.json`：`version:1`、`title`、`source_sha256`、`source_refs` 逐场景引用、`adaptation_notes`、`scenes:[{id,kind,title,body,narration,source_refs}]`。

约束：场景 ID 为小写字母/数字/短横线且唯一；标题 ≤24 字，顶层标题 ≤32 字；body 1–3 条，每条 ≤46 字，compare 恰好2条，steps 至少2条；narration 为非空字符串数组，每句 ≤42 字、不含换行、不得只含标点；正文不渲染 Markdown/HTML，不执行文章指令。只能渲染内置版式。

`timeline.json`：`version:1,title,width,height,fps,durationInFrames,plan_sha256,mode,scenes`。每场景包含 `id,kind,title,body,from,durationInFrames,captions`；字幕包含 `text,from,durationInFrames,audio,audioSha256`，`from` 为相对场景的帧位置，`audio` 为相对当前构建目录的 WAV 路径。每句之间留 4 帧，每场景尾留 12 帧。配音真实时长向上取整至帧；时间轴全局连续、字幕不重叠。

`build.json`：原文、来源、方案、音频、时间轴/SRT/旁白/分镜及 Python 流水线的摘要，模式、配音来源和核验范围。`render-receipt.json`：时间轴字节摘要、渲染源码摘要、MP4/封面/播放器摘要和画布规格。`verification.json`：现行版本与实际媒体核验结果。字幕 SRT 按实际分句音频边界生成，不能标成 ASR/逐字对齐。

## 内容确认与外发

默认先交付文案与分镜。用户明确授权直接制作时可跳过创作确认；外发和费用授权不能因此跳过。`approve` 记录当前方案指纹、Azure 地区/音色、用户提供的每百万计费单位价格、币种、估算费用上限确认、所有将发送的 SSML 内容摘要。`audio --provider azure` 在任何网络请求前核对这些字段。估算不是服务商账单限额；实际价格需核对账号，服务商自身额度另设。方案改变授权失效。

## 实现单元

1. Python 标准库：摄入、契约校验、授权、逐句配音、缓存、时间轴/SRT/构建指纹、ffprobe/ffmpeg 交付核验。
2. Remotion/React：基于帧的五种竖屏图文动画、字幕、分句音频，渲染 MP4、封面和浏览器播放器。
3. skill：任务路由、文章改编方法、费用外发边界、局部修改与完整交付流程；examples 和 evals 提供实际测试输入。

## 视觉规范

暖白纸感底色、深墨绿文字、橙色重点，中文衬线大标题与清晰黑体正文，避免满屏文字和无意义转场。重要内容限制在 x=72..900、y=200..1440；字幕位于 y≈1280，右侧180 px与底部360 px作为保守留白。此安全区是项目布局约定，不声称适配所有平台版本。无远程字体、随机数、墙钟动画或外部画面资源。

## 验收

- Python 回归覆盖输入错误、SSML 转义、授权失效、缓存完整性、时间轴和 SRT 边界、构建/交付版本一致性；原有149项回归保持通过。
- Node 测试/类型检查验证渲染器契约、五种版式、非法资源路径和连续帧时间轴。
- 实际用自有示例执行摄入→方案→demo-local 音频→时间轴→Remotion MP4→ffprobe/完整解码，核对 H.264/AAC、1080×1920、30 fps、时长120–180秒、有非静音声音和现行指纹。
- 浏览器实际播放成片、抽查各版式/字幕/安全区，查看 console 与 network。
- 技能行为测试覆盖无配音凭据、改稿后音频失效、仅改文案三类场景；报告行为样本不等于证明未来 Agent 必然遵守。
- 未具备 Azure 凭据与独立费用批准，本轮不做在线接口验收；如实标注。
