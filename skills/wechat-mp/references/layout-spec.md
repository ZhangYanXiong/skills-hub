# 公众号排版规范（layout-spec）

> 用途：定义 `scripts/md2wx.py` + `scripts/themes/*.json` 的排版基线，以及新增主题时必须遵守的约束。
> 配套：`writing-playbook.md`（内容）、`compliance.md`（合规）、`SKILL.md`（工作流）。

---

## 0. 平台约束：先记住这几条硬规则

排版做的任何事，都必须先满足微信的编辑器限制，否则做出来也是白做。

| 约束 | 具体表现 | 应对 |
| --- | --- | --- |
| 只保留 `style` 属性 | `<style>`、`<link>`、`class`、`id` 全部被丢弃 | 所有样式内联到每个标签 |
| 不支持脚本 | `<script>` 被剥离 | 不做任何交互，纯静态 |
| 不吃外部 CSS | 字体、颜色、间距必须逐个标签写 | 由主题 JSON 统一注入 |
| 正文外链不可点 | 非微信域名的 `<a>` 只显示文字，点了没反应 | 链接改成文字描述，或放「阅读原文」 |
| 图片必须同域 | 外域图片被防盗链拦截，显示空白/占位 | 上传素材库换成 `mmbiz.qpic.cn` |
| 部分标签不稳 | `div`、`pre` 在不同客户端表现不一 | 容器统一用 `<section>` |
| 不支持 flex/grid | 老版本 WebView 缺支持 | 只用块级流式布局 + 内外边距 |

`md2wx.py` 已经把这些约束固化在输出里；改主题时不要引入 flex / grid / 绝对定位。

---

## 1. 字号与行距基线

公众号是手机单列阅读，字小了累眼，字大了像大字报。基线如下：

| 元素 | 字号 | 行高 | 说明 |
| --- | --- | --- | --- |
| 正文 | 16px | 1.85 | 15px 偏小、17px 偏散，16px 是主流安全值 |
| H1（文内大标题） | 22px | 1.5 | 后台标题框不显示在这里，文内 H1 慎用，多数文章直接用 H2 起 |
| H2（一级小节） | 18.5px | 1.5 | 页面的骨架，段前距要明显大于段后距 |
| H3（二级小节） | 16.5px | 1.5 | 用强调色，和 H2 形成层级差 |
| H4 ~ H6 | 15 ~ 15.5px | 1.6 | 弱化为「加粗段落」，不抢层级 |
| 图片说明 | 12.5px | 1.6 | 灰色，居中 |
| 表格 | 14px | 1.6 | 比正文小半档，避免表格撑爆 |
| 代码块 | 13px | 1.65 | 等宽字体，必须可横向滚动 |

**字间距** 0.3 ~ 0.6px。中文正文加一点点字距会明显透气；0.8px 以上会显得松散。

**段间距** 1.4 ~ 1.7em。段落之间靠间距分隔，**不要用空行**（空行在微信里会被压缩或不稳定）。

**对齐** 正文 `text-align: justify`。中文两端对齐视觉更整齐；但代码块、表格、说明文字不要 justify。

---

## 2. 颜色

| 用途 | 取值 | 说明 |
| --- | --- | --- |
| 正文 | `#24292f` | **不要用纯黑 `#000`**，纯黑在手机上刺眼且显得生硬 |
| 标题 | `#111827` | 比正文再深一档，形成层级 |
| 次要文字 | `#55606e` ~ `#6b7280` | 引言、说明、图注 |
| 强调色 | 主题 accent | 全篇只用 1 个强调色系 |
| 正文背景 | `#fff` | 微信阅读页本身就是白底 |
| 代码底 | 深色 `#1b2130` 一类 | 与正文形成强对比，但别用纯黑 |

**颜色数量硬上限：强调色 1 个 + 中性灰阶 2~3 个。** 一篇文章出现 4 种以上彩色，读者第一反应是「营销号」。

---

## 3. 标题层级

- **H2 是骨架**：建议每篇 3 ~ 6 个 H2，太少显得没结构，太多显得零碎。
- **装饰只给 H2**：主题里 `decoration` 支持 `bar`（左侧竖条）/ `underline`（下划线）/ `pill`（色块）/ `none`。
  - `bar` 最通用，技术文首选
  - `pill` 偏活泼，职场/成长文可用
  - `underline` 偏冷静，观点/评论文可用
- **H2 段前距 > 段后距**：例如 `margin: 2em 0 0.85em 0`。这是「视觉分组」的关键，做反了整篇会散。
- **H3 用颜色区分，不用装饰**：H2 有装饰块、H3 只有颜色和字重，层级自然拉开。
- **不要跨级**：H2 直接跳到 H4 会让读者以为漏了一节。

---

## 4. 正文与强调

- **不加首行缩进**。公众号惯例是段落间用间距分隔，缩进反而显旧。
- **`**加粗**` 用强调色而非纯黑**：纯黑加粗只增加重量，不加重点。用 accent 色加粗才是「划重点」。
- **`==高亮==` 慎用**：底色高亮一屏不要超过 2 处，多了就全是重点等于没有重点。
- **一段一件事**。单段超过 5 行（约 260 字）就该拆，手机上一屏大概 10~12 行。
- **避免整段引用原文**：引用块超过 4 行读者会直接跳过。

---

## 5. 列表

- **不用原生 `ul/ol`**。微信对列表符号和缩进的还原不稳定，`md2wx.py` 采用「自绘符号 + 悬挂缩进」：
  - `padding-left: 1.5em` + `text-indent: -1.5em`
  - 换行后自动与首行文字对齐，而不是回到符号下
- **符号用中文圆点 `•` 或数字**，符号本身用强调色，比正文略重。
- **嵌套最多 2 层**。手机上 3 层缩进后正文宽度不足，会频繁换行。
- **列表项之间留 0.55em 间距**，比段落紧、比行距松。

---

## 6. 图片

- **宽度恒为 100%**，`display: block`，避免行内图片产生基线空隙。
- **圆角 6px**（技术/商务），极简主题可为 0。圆角超过 12px 会显得廉价。
- **图注写在图下**：12.5px 灰色居中。有信息量的图必须有图注，否则读者不知道在看什么。
- **配图节奏：每 600 ~ 800 字一张**。纯文字超过 1200 字不配图，完读率明显下降。
- **图片宽度 ≥ 900px**：公众号正文区宽度约 677px，在 2x 屏上需要 1354px 才够锐利；压缩后低于 900px 会明显模糊。
- **不要用外域图片**，见 §0。

---

## 7. 表格

- **列数 ≤ 4**。超过 4 列在手机上必然横向滚动，读者体验很差；能拆成两张就拆。
- **必须可横向滚动**：`tableWrap` 加 `overflow-x: auto`。
- **表头浅底色 + 1px 边框**，不要用斑马纹（微信里容易渲染成错行）。
- **单元格文字 14px**，左对齐；数字可右对齐。
- **表格前后各留 1.4em 间距**，否则和正文黏在一起。

---

## 8. 代码块

- **深色底 + 圆角 8px**，与正文形成强区隔。
- **13px 等宽字体**（`SF Mono / Menlo / Consolas`），行高 1.65。
- **语言标签**在左上角小字显示（`showCodeLang`），让读者知道在看什么。
- **必须横向滚动**，绝不自动折行——折行的代码基本不可读。
- **单块代码 ≤ 30 行**。更长的拆成「关键片段」，完整版给仓库链接。

---

## 9. 引用与提示框

两种语义不同的块，不要混用：

| 类型 | Markdown 写法 | 用途 | 样式 |
| --- | --- | --- | --- |
| 引用 | `> 文字` | 引用他人观点、金句、原文 | 左细边框 + 浅底 |
| 提示框 | `> [!NOTE] 标题` | 前提说明、注意事项、警告 | 左粗边框 + 语义色 + 标题 |

提示框支持 4 种语义色，取主题 `colors` 中的 `note / tip / warning / important`：

```markdown
> [!NOTE] 本文前提
> 项目用的是 Spring Boot，但思路对 Go / Node 同样成立。

> [!WARNING] 别在项目中期动这层
> 已经 30 个以上接口时，改造收益覆盖不了回归成本。
```

**一篇文章提示框不超过 3 个**，否则会打断阅读节奏。

---

## 10. 节奏与留白

- **每 600 ~ 800 字换一次气**：配图、分割线、提示框、引用，任选其一。
- **分割线用于「话题切换」**，不是每节都加。全篇 1 ~ 3 条足够。
- **结尾不要堆「关注我」大字**：一个自然收尾 + 一句轻引导即可，见 `writing-playbook.md` §5。
- **开头前 3 行决定去留**：不要在开头放分割线、图片、长引用，直接进内容。

---

## 11. 禁忌清单

| 禁忌 | 原因 |
| --- | --- |
| 纯黑正文 `#000` | 手机上刺眼，阅读疲劳 |
| 4 种以上彩色 | 一眼营销号 |
| 整篇居中 | 中文长文居中极度难读（标题可居中，正文不行） |
| 每段都加粗 | 等于没有重点 |
| 表格超过 4 列 | 手机横向滚动 |
| 代码自动折行 | 不可读 |
| 首行缩进 | 过时的排版习惯，与公众号惯例冲突 |
| 用空行当间距 | 微信里空行表现不稳定 |
| 表情符号当装饰 | 超过 3 个就显廉价，且部分设备显示为方块 |
| 外域图片 / 外链 | 见 §0，直接失效 |

---

## 12. 主题对照表

| 主题 | 适用内容 | 视觉特征 |
| --- | --- | --- |
| `tech` 科技蓝 | 技术拆解、产品分析、工程实践 | 蓝色强调，H2 竖条，深色代码块 |
| `growth` 成长橙 | 职场经验、成长复盘、方法论 | 暖橙强调，H2 色块，行距更松（1.9） |
| `minimal` 极简黑白 | 观点评论、深度思考 | 黑白配色，H2 下划线，加粗带下划线 |
| `elegant` 商务藏青 | 品牌稿、正式发布、行业分析 | 衬线字体，藏青强调，H1 居中 |

选择原则：**内容越硬，主题越素**。技术文用 `tech`，观点文用 `minimal`，品牌稿用 `elegant`。

## 13. 新增主题

在 `scripts/themes/` 下加一个 JSON 即可，**不需要改任何代码**。

最小示例（继承已有主题，只覆盖差异）：

```json
{
  "name": "mytheme",
  "label": "我的主题",
  "extends": "tech",
  "colors": { "accent": "#7c3aed", "accentSoft": "#f5f3ff" },
  "styles": {
    "h2": { "decoration": "pill" },
    "body": { "fontSize": "16.5px", "lineHeight": "1.9" }
  }
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `extends` | 父主题名，深度合并，只需写差异 |
| `colors` | 语义色板，`accent` 必填；`note/tip/warning/important` 供提示框用，每个可有 `*Soft` 浅底版本 |
| `styles.<元素>` | 键名用 camelCase（内部转 kebab-case），值即 CSS 值 |
| `styles.h2.decoration` | `bar` / `underline` / `pill` / `none`，仅 H2 生效 |
| `styles.h2.barWidth` | `bar` 装饰的竖条宽度 |
| `showCodeLang` | 是否显示代码块语言标签 |
| `hrGlyph` | 分割线字形，如 `· · ·`、`— — —` |
| `wrapper.maxWidth` | 预览页内容宽度，默认 677px |

改完在仓库根目录执行以下命令确认能被加载，再渲染一篇样例看效果：

```bash
python3 -I -B skills/wechat-mp/scripts/md2wx.py --list-themes
```
